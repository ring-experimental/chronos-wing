# 턴제 모드 계획

작성 2026-11-08. 워크트리 `chronos-wing-wt/turn`, 브랜치 `turn/base`(main d6ad921 기준).

## 사용자 결정

- 본편 스토리를 따라가는 스탠드얼론 모드. 본편 세이브 슬롯과 연계하지 않는다.
- 스토리모드 엔딩(퀘스트 34 완료) 뒤 메인메뉴에서 열린다.
- 레벨 디자인을 완전히 새로 짠다. 본편처럼 가방 칸 부족에 시달리지 않는다.
- 전투는 사이드뷰 턴제, 동료 참전 최대 4인(2026-11-08).

## 구조(제안, 확인 전)

- 같은 엔진을 모드 전용 저장 폴더(`save_dir/turn/`)로 돌린다.
- 스토리, 대사, 맵 이동은 원본 스크립트 엔진 그대로. 바꾸는 것은 전투와 레벨 디자인 표(몬스터 수치, 출현, 경험치, 드랍, 상점, 생산)이고 원본 파일은 두고 덮어쓰기 표로 한다.
- 필드 몬스터는 심볼 인카운터: 실시간 공격을 끄고 닿으면 전투 화면으로 넘어간다. 이기면 원래 처치 경로(경험치, 드랍, 도감, 사냥 카운트)로 처리한다.
- 전투 화면은 RmlUi와 스프라이트 그리기로 새로 만든다. 번역 코드에는 훅만 건다.
- 원작 시스템 대응: 3클래스 스킬 → 커맨드·연계기, 5종족 상성 → 약점, 화상·눈사람·방귀 → 상태이상, 보스 도주 → 전투 중 도주와 추적, 기원 → 전투 전 버프.
- 가방: 재료는 칸 제한 없는 재료함, 물약은 전투 아이템 목록.

## 단계

1. 조사: 필드 몬스터 구조와 접촉, 처치 경로, 일시정지 방법. 몬스터·주인공·동료 동작 번호 규약.
2. 시제품: 한 맵에서 몬스터 접촉 → 턴제 전투(주인공 + 동료) → 필드 복귀.
3. 전투 규칙과 스킬 변환.
4. 스토리 전투 목록(퀘스트 0~34)과 보스전 변환.
5. 레벨 디자인 설계표와 도구, 전면 적용.
6. 메뉴 해금, 전용 저장 폴더, 가방 정리.

## 조사 결과(2026-11-08)

주소는 Ghidra 주소(`client.bin` + 0x100000), GOT = 0x19c8d4.

### 필드 몬스터

- 엔티티 종류 3이 몬스터, 2가 주인공(0x147434 → 0x1b0e58), 1이 NPC와 동료. hd2d `data.md` 표는 1과 2가 반대로 적혀 있다.
- 필드 몬스터 목록 `*(GOT 0x20)`: 포인터 50칸, 개수 +0xc8. 구조체 0x2bc바이트: +8/+0xc 발, +0x18 활성, +0x1c 맵, +0xa8 EMD id, +0xac 동작 상태(5 죽는 중, 7 죽음), +0xae 방향, +0xb1 등급(0 보스, 2·3 일반, 4~6 특수), +0xb3 속성(종족), +0xd0 이름, +0xec/+0xf0 HP/최대, +0x101 레벨, +0x138 남은 재출현.
- 갱신 1단계 0x148bfc(접촉 0x148ba4(m, 0) 포함), 2단계 0x1495f8. 몬스터 → 주인공 피해 0x14de84, 주인공 → 몬스터 0x135a04, 피해 적용 0x14ad54(m, -피해, 종류), 보상 0x14aa54(드랍, 경험치, 사냥 카운트, 도감).
- 원본에 무리 개념은 없다. 소환만 묶음이 있다.
- 보스: 구조는 같고 생성 경로가 다르다(0x140a64, 보스 슬롯 `*(GOT 0x194)`). 도주는 누적 피해·HP 문턱으로 0x14e858 이벤트 동작. 죽으면 0x177ddc가 페이드와 뒤처리를 한다.
- 주인공: +0xec/+0xf0 HP, +0x114/+0x118 MP, +0x101 레벨, +0xb1 클래스, +0x11c 소울링크 동료 포인터. 공격 0x101ff4(슬롯)×0x102188%, 방어 0x101ef4(종류), 추가 감소 0x101f6c, 상성 0x12e514(줄 때)/0x12e6ec(받을 때).
- 동료 표 0x1a9e58(0x74×10): +4 이름, +0x35 레벨, +0x48 EMD id. 합류 여부는 스토리 변수(0x1a2618 + 0x7b4)로 판정(네트워크 모드와 같은 표). 동료 전투 수치는 클라이언트에 없다.

### 그림

- 몬스터: EMD/M 레코드 +2 묶음(EMS), +4 시트 그림 3장, +10 팔레트(EMP) 3개, +16 C0 번호. C0 표가 [상태][방향 0~3] → (동작, 방향, 효과)를 준다. 상태 0 대기, 1 이동, 2 피격, 3 사망, 4 기절, 5·6 넉백, 7~ 공격(보스 9~). 보스는 피격·넉백 동작이 없다.
- 프레임 시간은 데이터에 없다. 한 틱 한 프레임, 기본 25fps(40ms).
- 주인공: 동작 묶음 `H/S<클래스>`, 시트 0 `HIMG/000/<장비칸1>`, 1 `HIMG/001/<칸2>`, 2 `HIMG/002/<클래스>/<칸0>`, 3 `HIMG/003/<클래스>`(장비 번호 0x128f7c). 동작 2 전투 대기, 3 이동, 5 피격, 8 사망, 9~ 공격·스킬. `CM/F`는 대화창 얼굴 애니메이션이다.
- 동료: 전투 묶음이 EMD/M 49~57(55는 포포이)에 있다. 공격 동작은 하나뿐이고 스킬 동작은 없다.
- 방향: EMS에는 0~2만 있고 3은 2의 좌우 반전. 0 위, 1 아래, **2 왼쪽, 3 오른쪽**(2026-11-08 필드에서 왼쪽 키 → 주인공 +0xae 2, 오른쪽 키 → 3으로 확인. 그 전의 "2가 오른쪽"은 자체 그리기의 반전 처리 때문에 거꾸로 본 것이었다).
- 기본(4바이트) 부품 플래그 `(fl >> 5) & 3`이 뒤집기다: 1 좌우, 2·3 상하(0x17ebda → 0x17f354~). 반전 방향은 dx 부호만 바꾸고 뒤집기를 바꾼다(0x17f366). 그래서 좌우로 뒤집힌 부품은 dx가 오른쪽 끝이다. 주인공 무기가 이 부품이다.

## 시제품(2026-11-08)

`CHRONOS_TURN=1`로 켠다. 코드는 `native/restored/turnbattle.c`(전투), `turnspr.c`(그리기), `turn.h`.

- 계기: 몸이 닿음(0x148bfc 감싸기, 0x148ba4), 몬스터 공격(0x14de84 감싸기, 기습: 적이 먼저 한 바퀴), 주인공 타격(0x135a04 감싸기, 선제: 아군이 먼저 한 바퀴). 턴제 모드에서는 필드의 실시간 피해가 없다.
- 무리: 닿은 몬스터에서 72px 안의 싸울 수 있는 몬스터, 최대 3마리(정한 값).
- 파티: 주인공 + 소울링크 동료 + 합류한 동료 순으로 최대 4인. `CHRONOS_TURN_ALL=1`이면 시험용으로 모두 합류로 본다.
- 화면: 게임을 멈추고(main.c `frozen`) 배경 버퍼(화면 구조체 +4, 캐릭터 없는 바닥)를 어둡게 깐 뒤 그린다. 적은 왼쪽(오른쪽을 봄), 아군은 오른쪽 두 줄. 아래 창은 게임 창틀과 글꼴(0x172aa8, 0x12c50c, 색은 0x12d734).
- 명령: 공격, 강타(주인공만, MP 15, 1.8배), 방어(받는 피해 절반), 도망(60%, 보스 있으면 불가). 대상은 방향키로 고른다.
- 피해: 아군 → 적은 원본 0x135a04 꼴(공격력 - 0x14ebf0 방어, 주인공은 상성 보정). 적 → 주인공은 원본 0x14de84와 같은 식(0x14e494 공격력, 치명타, 0x101ef4 + 0x101f6c, 상성). 적 → 동료는 공격력 - 방어. 동료 수치는 네트워크 방어진과 같은 정한 값(HP 100+40L, 공격 10+4L, 방어 5+2L). 빠르기도 정한 값.
- 끝: 이기면 0x14ad54로 원래 피해 경로에 넘겨 필드에서 죽는 동작 → 보상이 나온다(battle 세이브에서 경험치 0 → 13, 상태 7 확인). 전멸은 시제품이라 HP 1로 필드에 돌아간다. 끝난 뒤 2.5초 동안 다시 마주치지 않는다.
- 시험 명령: 제어 파일 `turn nearest`(가장 가까운 몬스터와 전투).

확인한 것(macOS, battle 세이브, 폭 240·400·640): 접촉으로 열림, 4인 파티 표시, 공격·방어 명령, 적 차례, 승리 뒤 경험치와 몬스터 죽음, 폭별 배치.
확인 못 한 것: 기습·선제 계기, 강타·도망, 보스, 여러 마리 무리, 전멸, 소리(전투 음악·효과음 없음), Android·터치, 실제 합류 동료가 있는 세이브.

## 스토리 연동(2026-11-08)

밸런스와 상관없이 스토리 진행과 전투 전환을 시험하려는 단계다. 조사 노트 원본은 세션 scratchpad `research/boss.md`, `story.md`(퀘스트별 트리거 사슬 `chain.txt`).

### 조사 결과

- 스크립트는 몬스터를 만들거나 지우거나 전투를 강제하지 않는다(명령 87개 전수). 전투가 스토리에 닿는 길은 처치·아이템 목표뿐이다.
  - 명령 0x20 `[mon u16, 수, 퀘스트]`가 처치 목표(`0x128b64`, 종류 99)를, 0x21이 아이템 목표를 `*(GOT 0x528)`(8바이트 × 30)에 넣는다.
  - 보상 `0x14aa54` → `0x128ce0`이 처치 수를 올리고, 필요 수에 닿는 순간에만 지금 맵의 메인 1(머리 h3 = 퀘스트, h5 = 0)을 돌린다. 그때 스크립트가 돌고 있으면 버려진다(`0x136d38`).
  - 아이템 목표는 가방이 바뀔 때마다 다시 센다(`0x128d98`).
- 전투가 필요한 메인 퀘스트: Q7 빙설기(EMD 7), Q9 모그(18), Q11 결계석 ×10(211), Q14 일지 조각 드랍, Q16 모그 2차(19), Q17 모래상어(2), Q22 드래곤에너지 결정 ×10 드랍, Q24 가르둠(13, 맵 54의 메인 1은 비어 있어 거기서 잡으면 원본도 진행 안 됨), Q27 모그 3차(20), Q28 기계에너지 결정 ×20 드랍, Q34 야누스 심장(11)과 진야누스(12). 나머지 24개는 이동·대화·칸뿐이다.
- 보스는 일반 몬스터 목록(GOT 0x20)에 들어가고 같은 갱신·피해 함수를 쓴다. 보스 id는 지역 표에서 고르고(`0x1802d4`), 생성은 `0x140a64`, 보스 포인터는 `*(GOT 0x13c)` +0. 보스는 경로 표(+0x1bc)를 따라 맵을 옮겨 다니고 현재 맵은 +0x194다(`0x14b460`).
- 보스 "도주"는 다른 맵으로 달아나 계속 싸우는 것이다. `0x14ad54` 안에서 누적 피해 +0x1d0 ≥ 최대 HP × +0x17e%이면 도주 3, HP ≤ 최대 × +0x17f%(한 번, +0x19a)이면 도주 4 → `0x14e858`. 스토리 변수와 무관하다.
- 보스 죽음: 상태 3 → 보상 → `0x149c0c` 쓰러진 자세(상태 15). 스크립트·맵 이동 없음. 스토리는 보상의 처치 수로만 이어진다.
- 등급: 0 보스, 2·3 일반, 4 채집 대상(결계석, 광석·약초 덩이, 책장, 상자, 맞을 때마다 드랍), 5 에너지·자폭병(죽을 때 터짐, 결정 드랍), 6 쓰는 곳 없음.
- 주인공 쓰러짐: HP < 1이면 `0x132510` → `0x140dbc` → GAME OVER 창(긴급 부활 / 게임종료).
- 연습 맵 178·179(0xb2·0xb3)는 몬스터가 죽지 않고 보상도 없다(`0x1750f0`).

### 반영

- 전투에 적이 준 피해 합을 기록하고, 끝날 때 원본 피해 함수 `0x14ad54`로 넘긴다. 이기면 HP만큼, 아니면 준 피해만큼 넘긴다. 그래서 죽음·보상·처치 수·보스 쓰러짐 연출과 보스 도주 문턱이 원본 계산 그대로다. 피해를 막는 보호(+0x295 소환수 보호, 도주 동작)는 이긴 적에 한해 푼다. 소환수부터 정리한다.
- 보스 도주: 전투 중 보스가 원본과 같은 문턱을 넘으면 "<이름> 달아났다!"로 전투를 끝낸다. 필드에서 원본이 도주시킨다.
- 소환수를 부른 몬스터와 싸우면 소환수 목록(GOT 0xbfc)을 먼저 적으로 넣는다. 적은 최대 5마리(정한 값).
- 같이 싸울 몬스터는 원본 판정 `0x14b460`(지금 맵에 있음)으로 고르고, 전투 시작은 `0x14b2cc`(칠 수 있는 상태, 대사 중 아님)를 더 본다.
- 등급 4 채집 대상은 전투가 아니라 원본 실시간 타격 그대로다. 연습 맵도 원본 그대로다.
- 전멸하면 주인공 HP 0으로 돌려보내 원본 쓰러짐 → GAME OVER 창으로 간다.

### 시험 도구(제어 파일)

`turn quest N`(장면 시작 상태 적용 + 장면 스크립트), `turn quests`, `turn qset N V`, `turn flag N V`, `turn warp M X Y`(스크립트가 끝난 뒤 옮김), `turn objective Q EMD N`(명령 0x20과 같은 등록), `turn spawnboss EMD [here]`, `turn boss`, `turn mons`, `turn areas`, `turn win`, `turn lose`. 코드 `native/restored/turntest.c`.

### 확인(macOS, battle 세이브, 폭 400)

- 모그 1차: 맵 163에서 목표 등록 → 보스 생성(맵 165) → 전투에서 도주 문턱 → 필드에서 원본 도주(HP 601, 맵 166) → 쫓아가 승리 → 상태 15, 경험치, 처치 트리거로 다음 장면(모그 대사, 맵 1)까지.
- 빙설기, 모래상어, 가르둠, 모그 2차, 야누스 심장, 진야누스: 전투 화면 표시와 승리(주인공 옆에 생성해서 시험). 모그 3차는 기습 전투 표시까지.
- 드래곤에너지(등급 5): 전투, 승리.
- 결계석(등급 4): 원본 타격으로 부서지고 처치 목표 1/1.
- 전멸 → GAME OVER → 긴급 부활 → 필드.

## 연속 플레이 Q0~Q21(2026-11-08)

새 게임에서 시작해 퀘스트 0~21을 이어서 진행했다(Q22 진행 중 멈춤). 스토리 값은 건너뛰지 않았고, 이동만 시험 도구 순간이동(`turn warp`)으로 줄였다. 전투는 턴제로 했다(보스 일부와 간극은 `turn auto ok win` 자동 승리). 시험 세이브는 스크래치패드 체크포인트(q5, q7, q8, q10~q21)에 있다.

- 원작 경로로 확인: 빙설기(Q7, 맑은 새벽 착륙 시 지역 보스 → 도주 → 다른 맵에서 처치 → 열쇠 → Q7 완료), 모그 1차(Q9, 처치 트리거), 결계석 10개(Q11, 원작 타격), 모그 2차(Q16, 퀘스트 113 처치 트리거), 모래상어(Q17, 착륙 시 지역 보스 → 처치 → 목표 1/1 → 보고). 전멸 → GAME OVER → 긴급 부활(100원 결제 확인 2단계)도 여러 번 거쳤다.
- 턴제 승리 뒤 드랍은 몬스터 자리에 떨어지고 걸어서 주우면 들어온다("인간에너지 결정" 획득 표시 확인).
- 모그 1차 전투에서 모그가 죽은 뒤 남은 소환수에게 전멸했는데 처치가 인정됐다(정산이 죽은 적을 원본 피해로 넘기므로). 원작에서 보스를 잡고 소환수에게 죽는 것과 같은 결과로 본다.
- 보스는 지역 표가 월드맵 착륙(`0x180060`) 때만 채워진다. 순간이동으로 지역에 들어가면 보스가 없다. 빙설기는 지역 표 칸 0·1(4~12시, 날씨 맑음)에만 있다. 시각은 `*(GOT 0x1690)+4`, 월드맵 한 칸 이동에 2~3시간 흐르고 필드에서는 흐르지 않았다.
- 비공정 출항은 리키 과제(56·57)를 끝내야 한다(제작 아이템 0/1, 0/12). 제작을 건너뛰려고 `turn give`로 원본 지급 함수를 불러 넣었다(지름길).
- Q14 일지 조각은 부탁 퀘스트 114를 받지 않으면 NPC가 기본 분기로 바로 맵 82로 보낸다. 이 경우 드랍 수집 없이 끝난다.
- 시험 도구 문제였던 것: `turn auto`(끄기)가 인식되지 않아 확인 키가 계속 눌림(생산 화면이 안 닫히는 것처럼 보임), 같은 맵 안 순간이동 직후 치면 입장 스크립트가 도는 중이라 처치 트리거가 거절됨, 지역 자원이 안 올라온 맵(101·102)으로 순간이동하면 게스트 메모리 오류(턴제 꺼도 같음), 메뉴 커서 기억 때문에 저장 매크로 실패.
- 모그 배 조우(부탁 퀘스트 117)가 Q16 이후 월드맵 이동마다 거의 매번 일어났다. 원작 확률인지 확인하지 않았다.
- 멈춘 곳: Q22. 간극의 에너지(등급 5)는 원작에서 닿으면 자폭하는 몬스터인데 턴제에서는 닿을 때마다 전투가 열려 맵 안에서 거의 움직일 수 없다. 용족에너지(EMD 75, 맵 186·188·189)를 30회 넘게 이기고 근처를 밟았지만 드래곤에너지 결정(47/8)은 0개였다. 결정 드랍 확률, 가방이 찼는지, 다른 아이템 번호인지는 확인하지 못했다. 간극 안에서는 저장이 안 된다.

## 자폭 에너지와 기절(2026-11-08, 사용자 요청)

사용자 결정: 자폭 에너지는 닿으면 터지는 것이 아니라 턴제 전투에서 1턴 이상 지나면 터지고, 기절 상태면 터지지 않는다.

- 기절: 원본 경직(`0x14b0e0`)과 같은 문턱을 쓴다. 이번 전투에서 받은 피해 누적이 최대 HP × `+0x124`%에 닿으면 기절하고 다음 자기 차례를 쉰다. 풀린 뒤 한 번 행동할 때까지는 다시 기절하지 않는다(원본 경직 사이 대기 `+0x1d4` 대신 정한 값). 적 HP 막대 아래에 "기절"을 띄운다.
- 자폭(등급 5): 자기 차례를 한 번 보낸 뒤(첫 차례는 "몸이 빛나기 시작했다!") 다음 차례에 아군 전원에게 공격 피해를 주고 죽는다. 그 차례에 기절이면 쉬고 터지지 않는다. 정산은 원본 자폭(`0x148e44`가 HP 전부를 `0x14ad54`로 넘김)과 같게 HP 전부를 피해로 넘겨 보상이 나온다.
- 확인: 간극(맵 189)에서 예고 → 폭발 → 승리, 맵 96 보스(리바이어선)와 일반 몬스터 기절과 "기절해서 움직이지 못한다".
- 남은 점: 보스 문턱이 1%(리바이어선)라 거의 매번 기절해 한 차례 걸러 행동한다. 폭발 피해는 공격 1회와 같아 임시 동료 수치(HP 140)에서는 한 번에 동료가 모두 쓰러진다.

## 자동 줍기, 보스 기절 제외, 연속 플레이 Q22~엔딩(2026-11-08)

- 사용자 결정: 보스는 기절하지 않는다. 드랍은 전투 뒤 자동으로 줍고 무엇을 얻었는지 알린다.
- 자동 줍기: 드랍은 `*(GOT 0x15c)` 목록 개체(+0x24 종류, +0x22 id, +0x25 이름, 생성 `0x117d7c`)다. 처치가 있던 전투가 끝나면 4초 동안, 전투 전부터 있던 드랍을 빼고 하나씩 원본 줍기 `0x143f1c(사각형)`를 부른다. 가방 넣기, 원본 획득 표시, 수집 퀘스트 집계(목표 표 현재값)가 원본 그대로 돈다. 알림은 필드 HUD(`0x1444cc` 감싸기, padhint.c)에서 화면 위에 "획득 이름 xN"을 3.5초 띄우고, 가방이 차서 못 주우면 그 줄을 붙인다.
- Q22 결정 0개였던 원인: 전투 뒤 드랍이 몬스터의 필드 위치에 떨어지는데 줍지 못했다. 시험 때 본 "드래곤에너지 결정" 글은 바닥 드랍 이름표였다. 자동 줍기 뒤 Q22 목표가 3/10 → 10/10으로 차서 처치 트리거가 실행됐다.

## 그림을 원본 그리기로(2026-11-08, 사용자 지적)

지적: 캐릭터·몬스터가 원작과 다르게 보인다. 팔과 무기가 떨어져 있고 자폭 에너지는 흰 배경이 남는다.

원인: 전투 화면이 그림 형식(EMS, 시트, EMP)을 직접 읽어 다시 그렸는데, 부품 뒤집기·자리·투명색 처리가 원본 그리기와 달랐다.

반영(`turnbattle.c`, 자체 그리기 `turnspr.c`는 C0 표 읽기만 남김):
- 그리기는 원본 `0x17ead0(화면 *(GOT 0x2c), 그림, 동작, 방향, &프레임, x, y, 0, -1, 0)`을 부른다. 필드의 몬스터(`0x149064`)와 주인공(`0x13549c`)이 부르는 것과 같다. 방향 3이 2의 좌우 반전이다.
- 그림 객체(0x70바이트): 적은 필드 개체 +0x38, 주인공도 필드 개체 +0x38(장비 시트 포함)을 그대로 쓴다. 동료는 빈 개체(0x2bc)에 +0xaa 묶음, +0x10c 그림, +0x112 팔레트를 넣고 원본 `0x14efb8`, `0x14f040`으로 싣는다(초기화 `0x17df3c`, 해제 `0x17dfc4`).
- 프레임 수는 `0x17f44c`와 같은 표(+0x44 → 동작마다 0x48바이트). 필드 색 효과(+0x60~+0x65)는 그릴 때만 끈다. 사라지기는 원본 `0x17f438(그림, 1, 투명도)`.
- 몬스터 공중 높이 +0x29c를 뺀다. 발밑 그림자 `0x1046f0`을 필드와 같은 조건·크기로 그린다(동료는 주인공 크기).
- 피해 숫자는 게임 숫자 그림: 숫자 개체(0xa4)를 `0x118420(개체, 0, 0, 값)`으로 채우고 매 틱 `0x118528`로 그리고 `0x1184bc`가 참이면 끝. 원작은 주인공 피해를 숫자 없이 HUD 막대로만 보이므로 아군 피해도 몬스터와 같은 종류 0(주황)으로 정했다. 종류 2는 회색 `+숫자`라 쓰지 않는다.

확인(macOS, Q21 세이브, 폭 400, `CHRONOS_TURN_ALL=1`): 대포 주인공의 무기가 몸에 붙어 대기·공격 동작, 휘두르기 효과, 동료 3명 장식 부품 자리, 용족에너지(EMD 75)가 필드와 같은 구슬 모양(흰 배경 없음), 폭발 때 아군 4명 숫자 동시 표시와 승리, 아이스와이번 기습, 보스 18·7·13 표시, 아군 죽음 유령 효과와 사라지기.
확인 못 한 것: 다른 클래스 주인공(검·지팡이), 폭발 순간의 폭발 효과(전투 안에서는 없고 필드로 돌아간 뒤 원본이 터뜨린다), Android.

## 방향과 자폭 폭발(2026-11-08, 사용자 지적·요청)

- 지적: 오른쪽에 선 아군이 오른쪽(바깥)을 본다. 방향 2가 왼쪽이었다. 적은 3(오른쪽), 아군은 2(왼쪽)를 쓴다.
- 요청: 전투 안에서도 폭발. 원작 자폭 몬스터(등급 5)는 죽을 때 명령 2(+0xad)를 받고(`0x14a9f4`), C0 상태 2 동작이 끝나면(`0x1495f8`, `0x17f4e8`) `0x14ab54`가 드랍을 뿌린다. 상태 2가 폭발 동작이다(용족에너지 C0는 상태 0~2만 있다).
  - 전투: 자폭 몬스터가 죽으면(스스로 터지거나 맞아 죽거나) 상태 2를 끝까지 재생하고 바로 지운다. 맞을 때는 상태 2 대신 대기 동작을 쓴다. 터지는 동안 그림자는 없다.
  - 필드: 정산이 다시 명령 2를 주므로 1.5초 동안 그 몬스터의 프레임(+0x38+0x6a)을 0x7f로 넘겨 원본이 바로 끝 → 드랍으로 가게 한다. 폭발이 두 번 보이지 않는다.
- 전투가 끝난 직후 2~3프레임 흰 바탕에 주인공(보스면 보스도)이 검게 보이는 것은 원본 마무리 연출이다(`0x13549c`, `0x149064`의 0x0b 색). 그대로 둔다.
- 확인: 용족에너지 자폭(아군 4명 피해 → 폭발 동작 → 승리 → 필드에서 바로 "획득 마도원석"), 공격으로 잡을 때 폭발, 아이스와이번·모그와 아군이 서로 마주 봄, 주인공이 왼쪽을 보고 공격.

## 스킬·역할·상태이상·드랍 없애기(2026-11-09, 사용자 요청)

요청: 공격·강타뿐인 전투에 스킬을 넣는다. 주인공은 무기(클래스)별 원작 스킬과 효과, 상태이상 스킬(원작 몬스터별 상태이상 로직), 아이템 스탯 강화 로직으로 스테이터스 증가·파티 버프. 동료는 역할에 맞는 로직만 새로 만들고 동작은 공격 모션으로 통일. 필드에 아이템이 떨어지지 않게 하고(상자 부수기 등) 무엇을 얻었는지 창으로 알린다.
