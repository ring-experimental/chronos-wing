# 크로노스 윙: macOS 작업 계획

작성일 2026-10-30, 방향 변경 2026-10-31, 1~7번 완료, 9번 빌드 완료 2026-10-31. 다음 세션은 이 문서의 "다음 세션 순서"부터 시작한다.

## 결론

- 원본은 APK가 아니라 **KTF WIPI Clet**이다. 가이드의 재컴파일 트랙(libso2sdl3, 에뮬레이터 AVD, Frida)은 그대로 쓸 수 없다.
- **사용자 결정(2026-10-31): 최종 제품에서 WIE를 뺀다.** 소규모 프로젝트의 에뮬레이터에 계속 의존하는 것을 위험으로 본다. 게임 코드를 C/C++ 소스로 복원하고 SDL3 위에서 네이티브로 빌드한다.
- WIE 내부에 함수 훅을 넣어 점진 교체하는 안과 `wie-app` 배포 안은 폐기했다. 현재 WIE 포크는 원본 동작을 대조하는 기준으로만 쓰며, 산출물에 포함하거나 링크하지 않는다.
- 아래 "WIE 구동 시험", "SDL3 전체화면"은 이 결정 이전의 기록이다.

## WIE 구동 시험

위치: `~/private/reverse/tools/wie`(커밋 b91cc161), `cargo build --release` 성공.

```bash
~/private/reverse/tools/wie/target/release/wie <크로노스윙.zip 복사본>
```

키: 방향키, Space=OK, Shift 좌/우=소프트키, Backspace=CLEAR, 123/QWE/ASD/ZXC=숫자 키패드.

확인한 것(디버그 로그, 30초 실행):
- 크래시 없이 살아 있었고 `MC_grpFlushLcd`가 240×320으로 27초간 488회 호출됐다(약 18fps).
- 리소스 로드, 타이머, `MC_fsWrite`, 소리 재생 호출(`MC_mdaPlay`)이 동작했다.
- stub 호출은 메모리 조회, 볼륨, 백라이트, `MC_grpGetFont`, `MC_mdaUnk17` 등이다.

확인하지 못한 것:
- **타이틀 화면.** 창 캡처(터미널 화면 기록 권한 부여 후) 결과, 약 1분 동안 파란 하늘과 움직이는 구름만 보이고 로고·글자·메뉴는 없었다. 입력을 기다리는 장면인지 로고·글자 그리기가 빠진 것인지 미확인. 다음 세션 2번에서 키를 눌러 가장 먼저 확인한다. 창은 240×320 등배 크기라 확대가 없다.
- **입력과 진행.** 키를 넣어 보지 않았다. 새 게임, 전투, 저장, 불러오기 모두 미확인.
- **소리.** 효과음은 PCM(`ATR`), 배경음은 MIDI(`MTR`)다. WIE CLI는 MIDI를 포트로만 보내므로 macOS에서는 `work/play.sh`(FluidSynth + WIE `assets/1mgm.sf2`)로 실행해야 배경음이 난다. 음표 전달은 확인, 음색 품질은 사람이 판단. `wie-app`의 Android·Windows 배경음 경로는 미확인(Apple은 `wie-app/src/audio/apple.rs`가 같은 사운드폰트를 쓴다).
- **인증.** 게임이 `CERTIDATA` 파일을 쓴다. 온라인 인증이나 서버 접속이 진행을 막는지 미확인(`OffRun:0`의 의미도 미확인).

## SDL3 전체화면 (2026-10-31)

- WIE 포크 `src/cli/window.rs`를 winit/softbuffer에서 SDL3(`sdl3-sys`, 정적 빌드)로 교체했다. `work/play.sh`로 실행하면 전체화면이고, 게임 폭은 모니터 비율로 자동 계산한다(MacBook 16:10 = 512). 원본 zip 그대로 쓰며 `work/wide/*.zip`은 더 필요 없다.
- 옵션: `--windowed`(원래 크기 창), `--game-width N`. F11 전체화면 전환, macOS 종료는 Cmd+Q.
- 게임 코드는 여전히 WIE가 ARM 코드로 실행한다. C 소스 복원이나 재컴파일이 아니다. SDL3는 창·입력·표시만 맡고 소리는 기존 경로(rodio, MIDI)다.

## 와이드 화면 시험 (2026-10-30)

목표: 전체화면은 여백 허용, 필드는 가로로 넓게.

- ADF의 `DisplaySize`만 바꾼 복사본(`work/mkwide.py`, `work/wide/w400.zip`, `w512.zip`)을 돌리면 게임이 해당 폭으로 프레임버퍼를 만들고 하늘 장면을 전체 폭에 그린다. 바이너리는 수정하지 않는다.
- 필드, 메뉴, 전투는 미확인. 결과가 좋으면 `client.bin` 수정 없이 WIE 수정 경로를 유지하고, 깨지는 곳만 훅으로 고친다. 넓은 맵에서 판정이나 스크롤이 무너지면 C 변환 경로를 다시 검토한다.
- 240×320 관련 즉시값: W 115, W/2 54, H/2 227곳, 함수 213개. 정적 어림값이라 비코드와 무관한 값이 섞여 있다. W는 `0x11c9dc` 부근(42곳)에 몰려 있다.

### 타이틀 검은 블록 분석 (2026-10-31, 미해결)

- 증상: 512 폭 타이틀에서 검은 블록이 프레임마다 위치를 바꾼다(오른쪽 아래 x≈420~512, y≈104~320 / 왼쪽 위 x=0~50, y=0~105). 구름 층이 스크롤하다 생기는 틈으로 추정(UNVERIFIED). 그리는 함수는 아직 못 찾았다.
- 도구: `WIE_CTRL=<파일>`(WIE 포크 `src/cli/ctrl.rs`, 미커밋)로 `key <이름>`, `shot <ppm>`, `quit`. 실행 예 `work/tools/title.sh <zip> <출력폴더> ok ok`, 변환 `work/tools/ppm2png.py`.
- 디컴파일: `work/decomp/all.c`(함수 2,669개, 재생성은 `work/tools/DumpThumb.java`). Ghidra는 `JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home`, `-processor ARM:LE:32:v4t`, base 0x100000. 함수 시작을 push-lr로만 잡아서 누락이 있을 수 있다.
- 알아낸 것: 전역 구조체 `+0x48`/`+0x4c` = 화면 폭/높이, 읽는 함수 77개. 원작에 `폭 < 0xfb` 분기와 `min(폭, 240)` 고정 UI 코드(`0x11d2b0`, `0x11c9dc`, `0x11e83c`)가 있다. 즉 넓은 화면을 어느 정도 고려했다.
- 막힌 방법: 리소스 문자열 정적 참조 검색, `--profile-out`(네이티브 실행에서는 게임 주소가 안 잡힘).
- 사용자 플레이 확인(2026-10-31): 와이드에서 전투 화면 깨짐은 발견되지 않음.
- 호출자 로그: `RUST_LOG=wie_ktf::runtime::wipi_c=trace`로 `wipic call <id> from <lr>`이 찍힌다(WIE 포크, 미커밋). 리소스 로드는 전부 공통 로더 `0x183f44`를 거쳐 LR만으로는 호출자를 알 수 없다. 스택까지 기록해야 한다.
- 타이틀 구름이 아닌 것으로 확인: `0x173ddc`(타일 169개를 400×400 버퍼에 합성, 타이틀 중 호출 0회. `0x180674`와 연결되어 월드맵으로 추정, 폭이 400을 넘으면 월드맵에서 같은 틈이 날 수 있으니 확인 필요), `0x17db94`(필드 오브젝트), `0x17e078`(데이터 파서).
- 타이틀 중 매 프레임 호출: `0x106998`(사각형 채우기) 프레임당 3회, `0x15010c`, `0x150244`, `0x183694`, `0x12d734`. 사각형 3회가 하늘을 그리는지부터 확인한다.
- 다음: 호출자 로그에 게임 스택을 함께 남겨 `0x106998`과 `/CM/TITLE*` 로드의 실제 호출 함수를 찾고, 거기서 그리기 코드를 따라간다. 수정은 EpicHearts처럼 해당 층을 끝까지 반복해 그리는 교체로 한다. WIE에는 게임 주소 단위 훅이 보이지 않았고(`core.rs` 검색 기준) 필요하면 새로 만든다.
- `work/bin`, `work/decomp`, `work/ghidra`, `work/shots`, `work/wide`는 원본 파생물이라 저장소에 올리지 않는다.

## 복원 기반 측정 (2026-10-31)

| 파일 오프셋 | 구역 | 근거 |
|---|---|---|
| `0x0`~`0x70` | 시작 코드, 재배치 상수 | 진입점 `0xc` 해석 |
| `0x70`~`0x1398` | 재배치 표 1,225개 | 시작 코드의 첫 루프 |
| `0x1398`~`0x13ac` | 이미지 머리(GOT 범위, BSS 범위, 실행 설명자 `0x9bec8`) | 시작 코드의 둘째 루프, BSS 474,328과 일치 |
| `0x13ac`~`0x8ef74` | 텍스트 580,572바이트 | 아래 측정 |
| `0x8ef74`~`0x9a340` | 읽기 전용 데이터(문자열, 점프표 대부분) | 코드 분기 없음, 첫 재배치 위치 |

## 복원 방식 시험 (2026-10-31)

재현: `codemap.py` → `thumb2c.py` → `clang`으로 `tr.dylib` 빌드(`work/trial/thumbrt.h`, `rt.c`) → `work/tools/trial.py`. 표본 600개 함수, 함수당 난수 입력 4개. 기준은 원본 Thumb를 Unicorn으로 돌린 결과다.

| 항목 | Thumb 기계 번역 C | Ghidra C |
|---|---|---|
| 컴파일 | 전체 3,253개 중 12개 번역 불가(모두 `svc 0xab`) | 표본 600개 중 49개 실패 |
| 원본에서 실행된 표본 중 일치 | 393 / 394 (99.7%) | 317 / 373 (85.0%) |
| 비교 불가(원본이 입력에서 멈춤) | 206 | 178 |
| 비교 범위 | r0, r4-r11, sp, 스택 밖 메모리 | r0(void 제외), 스택 밖 메모리 |
| 호출되는 함수 | 번역본 | 원본 코드(시험 대상 1단계만) |
| 실행 환경 | 64비트 macOS | 32비트 Thumb로 컴파일해 Unicorn에서 실행 |
| 읽기 | 레지스터 단위라 읽기 어렵다 | 읽을 수 있다 |

- Ghidra C는 32비트 전제다. 포인터를 `int`로 다루는 역참조가 15,347곳(함수 1,940개)이라 64비트 빌드에는 메모리 접근 층이 필요하다.
- 기계 번역의 불일치 1건은 `0x3404`가 부른 `0x198a0`이 함수 목록에 없어서 났다. 지도에서 탈락한 후보(`0x1a2dc`, `0x7f3c4`, `0x7f3e2`, `0x13fc`)와 함께 고쳐야 한다.
- 시험은 난수 입력이다. 실제 게임 경로와 WIPI 호출을 거친 경로는 검증하지 않았다. setjmp/longjmp는 아직 번역 런타임에 없다.

**결정: 2단 구조.** 기계 번역 C를 전체 기반으로 먼저 구동한다. UI와 수정 대상은 Ghidra C를 참고해 사람이 읽는 C로 함수 단위로 교체하고, 교체할 때마다 번역본과 대조한다. 둘은 같은 메모리 모델(32비트 게스트 주소 + 베이스)을 쓰므로 함수별로 섞을 수 있다. 번역본만으로는 "소스 복원"이 끝난 것이 아니다. 전체를 읽는 C로 옮길지는 구동 후 범위를 합의한다.

## 네이티브 호스트 (2026-10-31)

`native/`. 빌드와 실행은 `native/README.md`. 실행 파일이 링크하는 것은 SDL3와 시스템 라이브러리뿐이다.

- Java 층은 우회한다. `Clet` 네이티브 스텁을 읽어 C 진입점을 찾았다: `startClet` `0x592a4`, `handleInput` `0x593b0`, `pauseClet` `0x593f8`, `resumeClet` `0x59400`, `destroyClet` `0x59364`, `paintClet` `0x593f4`(비어 있음). 게임은 타이머에서 스스로 그린다. pause/resume/destroy는 아직 호출하지 않는다.
- 입력은 `handleInput(2=누름 3=뗌, 키, 0)`. 키 값은 WIE 기록으로 확인했다(위 -1, 아래 -2, 좌 -3, 우 -4, OK -5, 소프트 -6/-7, CLEAR -16, 숫자는 ASCII).
- 메모리: 게스트 주소 그대로. 이미지 `0x100000`, 표 `0x220000`, 스택 `0x400000` 아래, 힙은 그 위 60MB. 표 전역에 호스트 표를 직접 넣고 슬롯 값 `0xf0000000 | 표<<16 | 번호*2 | 1`을 `call_ind`가 분배한다.
- ARM 도우미 3개는 C로 대체했고, setjmp/longjmp는 게임 코드 호출이 없어 넣지 않았다. `svc 0xab` 함수 12개는 번역하지 않았고 불리면 오류로 멈춘다.
- 소리: MMF 47개를 빌드 때 이벤트 파일로 바꾸고(`work/tools/smaf2ev`) 내용 해시로 찾는다. 지금까지 누락 없음. 이득 값(MIDI -6dB, 파형 0.5)은 임시다.
- 미구현: `MC_grpDrawString`(시험 중 호출 없음, 호출되면 로그만 남김), 와이드 화면(폭 240 고정), `work/wipi-api.md`에서 시험 중 호출되지 않은 일부 슬롯은 로그 후 0을 돌려준다.

지도 수정: 먼 분기 BL 판정을 "거리 1500 이상이고 프롤로그 창 안" 또는 "BL 뒤가 데이터"로 바꿨고, 점프표는 직전 바이트를 거슬러 찾는다. 다른 함수 안의 진입점은 본문을 복제한다. 최종 지도: 번역 함수 3,075개, 점프표 225개, 먼 분기 338곳, 미분류 3,136바이트(0.54%). 위 "복원 기반 측정"의 표는 이전 지도 기준이다.

확인한 것:
- API 호출 순서: 시작부터 3,203건이 WIE 기록과 번호, 호출 위치까지 일치한다. 그 뒤로 갈라지는 원인은 아직 확인하지 않았다(타이머 시각 차이로 추정).
- 번역 일치 시험: 표본 600개 중 실행 가능한 386개 모두 일치(마지막 점프표 생성 수정 전 빌드 기준).
- 자동 입력으로 타이틀, 서버 끊김 메시지, 스토리 대화, 필드, 옵션 메뉴까지 진행. 재시작하면 게임이 쓴 저장 파일에서 이어진다. 무작위 입력 5분 동안 충돌 없음.

확인하지 못한 것: 픽셀 일치(6번), 전투, 메뉴에서 고른 저장, 실제 키보드 입력, 소리의 음색과 음량, 전체화면 표시(시험은 모두 창 모드).

5번 완료(2026-10-31). 결과는 "네이티브 호스트" 참고. 전투와 의도한 저장은 아직 시험하지 못했다.

6번 완료(2026-10-31). WIE와 네이티브에 같은 프레임 스크립트를 넣어 비교했다(`work/tools/framecmp.sh`, `framediff.py`, `framesheet.py`, `keys2frames.py`). 연속 중복을 뺀 프레임 열 기준으로 타이틀, 접속 실패 메시지, 스토리 대화, 필드 이동과 대화까지 WIE 5,365구간(고유 프레임 2,007개)이 순서와 RGB565 바이트까지 모두 일치했다. WIE를 종료한 330초 시점 뒤의 네이티브 프레임은 비교하지 못했다. 전투와 저장 화면은 이 입력으로 도달하지 못했고, 프레임 표시 간격(속도)도 비교하지 않았다. 기준인 WIE 자체가 실기기는 아니다. 같은 실행의 소리 최대값이 4.524로, 필드 구간에서 하드 클리핑이 발생하는 문제가 남았다.

7번 완료(2026-10-31). 타이틀 함수 `0x183694`를 `native/restored/title.c`의 읽는 C로 옮겼다. 하늘 두 층은 폭 320 타일 2장을 스크롤하는 구조여서 넓은 폭에서 틈이 났고, 남는 폭을 같은 간격으로 채웠다. 폭 240은 WIE와 3,171구간 일치, 폭 400·640은 620프레임 동안 검은 픽셀 0개. 교체 함수는 `native/restored/list.txt`에 적으면 번역기가 건너뛴다. 전체화면 기본 폭은 모니터 비율(240~640)이다. 폭 512에서 스토리와 필드까지 자동 입력으로 진행했으나 UI 깨짐을 전수 확인하지는 않았다.

전투 대조 완료(2026-10-31). 사용자가 네이티브로 튜토리얼을 지나 몬스터 맵에서 저장했다(복사본 `work/saves/battle`, 공개 금지). 같은 세이브, 같은 입력으로 WIE와 비교하면 타격 때 별 효과만 달라지는데, 같은 프로그램끼리도 달라지므로 시각 값 차이다. 양쪽 시계를 호출당 5씩 늘도록 고정하면(`CHRONOS_FAKE_TIME`, WIE는 `WIE_FAKE_TIME`을 켜고 컴파일) 4,666구간이 픽셀까지 일치한다. 실제 시계에서는 타격 효과가 실행마다 다르고 이는 정상이다. 폭 512에서도 같은 입력을 2,400프레임 돌렸고 충돌은 없었다. 저장 화면에 들어가는 자동 입력과 저장 후 파일 비교는 하지 않았다.

월드맵 확인 시도(2026-10-31). `0x173ddc`는 `/WM/SIMG` 타일 169개를 400×400 버퍼에 합성하므로 월드맵 코드가 맞다(`/WM/SHIP`, `/WM/POINT`도 있다). 호출 경로는 `0x1737bc` ← `0x13f2dc`이고 `0x13f2dc`의 호출자는 번역 코드의 직접 호출에서 찾지 못했다. 몬스터 맵 세이브(`work/saves/battle`)로 불러와 900프레임을 돌린 동안 `0x173ddc`, `0x180674`, `0x180718`은 불리지 않았다. 필드 메뉴(주인공, 스킬, 소지품, 퀘스트, 시스템)에도 월드맵 항목이 없고, `#`은 미니맵이다. 폭 640 표시 확인에는 월드맵이 열리는 세이브가 필요하다. 폭 400 초과에서 틈이 나는지는 아직 모른다.

월드맵 확인 완료(2026-10-31). 사용자 세이브 복사본 `work/saves/worldmap`(배 위, 공개 금지)에서 왼쪽 이동 뒤 5로 진입한다. 폭 240은 시계 고정 시 WIE와 2,232구간 일치. 폭 512·640에서 완전한 세로 빈 줄은 없지만 맵 이미지(반복 주기 약 400)가 좌우로 반복되어 같은 대륙이 두 번 보이고, 지명 표시는 한쪽에만 있다. 배 장면은 넓은 폭에서 맵보다 남는 양옆이 검게 나온다. 사용자 결정으로 가운데 지도 한 장 + 양옆 여백을 택해 `0x180674`를 `native/restored/worldmap.c`로 옮겼다. 폭이 지도보다 넓으면 카메라 X를 지도가 가운데 오는 값으로 고정한다. 폭 240은 시계 고정 시 WIE와 2,232구간 유지. 폭 402·512·640에서 자동 입력 3,000프레임 충돌 없음, 512·640은 반복 사라짐과 지명·배 위치 일치를 눈으로 확인. 진입 때 줌·모자이크(`0x180978`)가 여백에 번지는 문제는 사용자가 발견했고, 분기 함수 `0x1805f8`을 옮겨 효과 뒤 여백을 다시 지우게 고쳤다. 폭 240은 다시 2,232구간 일치, 폭 512·640은 지도 구간 여백 오염 0. 다른 지역으로 실제 이동은 미확인.

소리 클리핑 해결(2026-10-31). 원인은 음량이 아니라 음 누적이었다. 곡이 서스테인 페달(CC64)을 밟은 채 중단되면 신시사이저 채널에 상태가 남아 다음 곡의 음이 끝나지 않았고 동시 음이 887개까지 늘었다. 곡 중단, 반복, 종료 때 CC64와 채널 상태를 초기화한다(`native/host/audio.c`의 `synth_reset`). TinySoundFont의 CC121은 페달을 풀지 않으므로 CC64를 따로 끈다. 스토리·필드, 전투, 월드맵 약 150~170초씩 측정해 1을 넘는 샘플 0개, 최대값 0.69, RMS 중앙값 약 0.03~0.05. 사람 귀로 음색과 음량은 미확인. 모든 곡이 신시사이저 하나를 함께 쓰므로 MIDI 효과음이 BGM과 겹치면 서로 끊을 수 있는지는 미확인.

8. 첫 전투까지 튜토리얼이 길어 전투·저장 대조는 사용자 판단으로 뒤로 미뤘다. 스토리, 전투, 저장을 차례로 복원하고, 월드맵(400 폭 버퍼)을 와이드에서 확인한다. 이후 UI 수정은 복원 소스에서 진행한다.
9. Windows, Android 빌드. 빌드 완료(2026-10-31), 아래 참고.

9번 결과. `make windows`는 mingw로 `build/win`을 만든다. Windows에서 실행해 보지는 못했다(Wine, 게스트 없음). PE 의존성은 시스템 DLL과 SDL3.dll뿐이다. `make android`는 Gradle 없이 arm64 APK를 만든다. Android 15 에뮬레이터(소프트웨어 GL, 오디오 없음)에서 설치, 데이터 풀기, 가로 전체화면, 터치로 타이틀→스토리→필드, 메뉴, 뒤로 키, 백그라운드 복귀, 강제 종료 후 재실행을 확인했다. 콜드 부팅 직후 첫 실행이 스스로 종료하던 문제는 시스템 오버레이 갱신(`CONFIG_ASSETS_PATHS`)의 Activity 재생성을 SDL이 종료로 처리한 것이었고, 빌드 때 `android/patch_manifest.py`가 비공개 플래그를 더해 막는다(콜드 부팅 1회 확인). 실기기, 소리, 성능, 저장 후 불러오기는 미확인이다. 

검증 원칙: 함수를 옮길 때마다 WIE를 기준으로 프레임 해시나 API 호출 순서를 대조한다. 대조 도구는 WIE 포크의 `WIE_CTRL`과 `wipic call` 로그를 쓴다. 사람이 처음 플레이로 확인할 항목은 실제 키보드 입력이다(자동 시험은 `WIE_CTRL`만 사용).

UI 전환(2026-10-31). 게임 위 UI를 RmlUi 6.3으로 옮겼다. 패드는 게임 도움말(`tdf/HELP`)의 기본 조작을 따른다. 방향키, OK, 스킬 7·9, 소지품(`*`, 물약 선택에 오른손을 쓰므로 OK 바로 위), 지도(`#`, 오른쪽 위), 메뉴(CLR, 소지품 바로 위), 설정이고, 대사 중에는 OK와 그 위 스킵(`#`)만 남는다. OK와 5는 같은 입력에서 프레임이 동일했다. 대사 플래그 `0x1a2940`(컷신과 필드 대사에서 1, 필드·메뉴·월드맵·타이틀에서 0, 장면별 메모리 비교)을 데이터 모델 `dialog`에 묶었다. 스킬은 5, 7, 9 조합 커맨드이며 스킬 구매 전 세이브로만 시험해 실제 발동은 미확인. 1, 3, 0은 입력표에서 별도 처리되는데 유료 스킬 단축키로 추정해 패드에서 뺐다. 좌우 소프트키도 뺐다(메뉴는 CLR로 열린다). 게임이 직접 그리는 메뉴의 RmlUi 교체는 해당 함수 복원이 필요해 아직 하지 않았다.

패드 스킨(2026-11-01). `work/tools/mkskin.py`가 게임 메뉴 색(`#183c70`, `#305ca8`, `#f8c400`)과 로고 톱니 모티프로 PNG를 만든다. 원형 방향 다이얼, OK 메달 주변 호 배치의 7·9, 아이콘 버튼 구성이다. 실제 RPG 화면 자료는 얻지 못해 배치는 일반 관례를 따랐다.

배경음과 효과음 동시 재생(2026-11-01). 게임은 효과음마다 배경음 정지 → 효과음 → 정지 → 배경음 처음부터 재생을 호출한다(약 1.5초 끊김). `audio.c`가 이를 해석해 효과음이 끼어든 정지를 무시하고 같은 곡 재생은 이어서 튼다. 전투 측정에서 효과음 28회 동안 음악 재시작 0회, 0.5초 창 기준 무음 0, 최대값 0.84, 프레임은 WIE와 1,339구간 일치. 효과음 뒤 배경음 요청이 없을 때 실제 정지하는 경로는 코드만 있고 미시험이다.

패드 복원(2026-11-01). 사용자 요청으로 `1 3 0 L R`을 지도 버튼 왼쪽, 같은 묶음(`aux`)에 되돌렸다. 필드에서 L은 시스템 메뉴(저장하기, 환경설정, 도움말, 나가기)를 연다.

패드 표시 조건(2026-11-01). `0x1a2940`은 NPC 대화, 퀘스트 선택지에서도 1이어서 방향키가 사라졌다. 패드를 OK와 스킵으로 줄이는 조건을 `0x1a2cb1`도 1인 스토리 대사로 한정했다. 이 값은 프롤로그 스토리 대사에서만 1이고 타이틀, 필드, NPC 대화에서는 0이다. 프롤로그 뒤의 스토리 장면에서는 미확인.

대사 판별 재점검(2026-11-01). `0x1a2cb1`은 스토리 표시가 아니라 맵 이동을 거친 스크립트에서 켜지는 값(구조체 `0x1a2618` `+0x699`)이라 같은 맵의 대사에서는 SKIP이 뜨지 않았다. 이제 `game_in_dialog`가 스크립트 상태(`+0x32c`)가 대사(0x32, 0x35)일 때 켜고, 팝업(`0x1a2604`), NPC 메뉴(`0x2100bc`), 목록 대사(0x37, 0x38)에서 끄며, 실행 값(`+0x328`)이 200ms 꺼지면 끈다. `#` 처리는 `0x11ec54`에 있고 상태 0x33, 0x34, 0x37, 0x38, 0x39에서는 스킵을 받지 않는다. NPC 대사와 프롤로그에서 확인했고 SKIP을 터치하면 필드까지 넘어간다. 선택지 팝업과 0x37, 0x38은 실제 장면에서 보지 못했다.

스킬 단축키(2026-11-01). 구매 값은 주인공 구조체(`0x1b0e58`) `+600`이고 원본은 서버 응답 뒤 `0x15ab3c`에서 켠다. 서버가 없으므로 `native/host/api.c`의 접속 처리에서 키냥냥 구매(`0x2100b8`의 `+5`가 0x13, `+0x2b`가 3)만 성공으로 처리한다. 슬롯 상태는 `0x1b04d8`이다(`+3~5` 사용 여부, `+6~8` 스킬 번호, `+10`부터 슬롯별 입력 4개, `+2` 재생 중 슬롯). 스킬 메뉴 `단축키 등록/해제`로 켜고 끈다. 슬래쉬 콤보는 등록되고 슬래쉬, 스피어링은 거부된다. 와일드윙 안에서는 발동하지 않았다. 슬롯 3번 발동과 재시작 뒤 발동은 미확인. 패드의 `1 3 0`은 구매 값(`0x1b10b0`)을 데이터 모델 `shortcuts`에 묶어 구매 전에는 숨긴다.

유료상점 조사(2026-11-01). 보우머(NPC 유형 4, `DAT/SL`)의 `캐시구입`은 게임 내 고정 목록을 쓴다(`0x12a66c`, 표 `0x191c10`, `0x191c16`, `0x191c22`): 스킬 초기화 1, 특성 초기화 1, 부활석 10, 부활석 20, 고대비약 20, 허리주머니 추가 1. 상품 번호는 6~11, 가격은 표 `0x19b4b8`(800, 800, 500, 1000, 500, 500원). 구매 요청은 코드 4로 접속하고, 결과가 1이면 `0x16a320`이 초기화를 실행하거나 창고로 지급한다. 요청 코드는 `0x21004f`(`0x158a28`), 결과는 `0x210035`(`0x158ab0`)다. 처음에 이 두 주소를 잘못 넣어 구매가 `서버와의 연결이 끊어졌습니다`로 실패했고 고쳤다. 별빛마을 흑냥냥 세이브로 6개 상품을 모두 구매했다. 부활석 10, 20, 고대비약 20, 허리주머니 추가는 가방에 들어오고(부활석 10은 재시작 뒤에도 확인), 스킬 초기화와 특성 초기화는 `0x136340`, `0x1363c4` 호출과 `HERODATA` 변경을 확인했다. 이 세이브는 초기화할 내용이 없어 화면 변화는 못 봤다. 허리주머니 추가는 사용하면 없어지고 칸 표시가 바뀌지만 새 칸에 물건을 넣어 보지는 않았다. 서버 목록을 쓰는 `캐쉬샵`(요청 1,0x28과 1,0x29)은 NT 거래 쪽이고 별도다.

세이브 옮기기(2026-11-01). 캐릭터 관리의 복구 팝업(`0x1b0e18` 상태 3, 하위 0)을 `native/restored/charmenu.c`가 들여오기/내보내기로 바꾼다. `restored/list.txt`의 `wrap`은 원본을 `orig_f_`로 남긴다. 묶기와 검증은 `native/host/savefile.c`. 세이브 앞 16바이트는 복호화한 내용의 해시다(`0x13fc74`, `0x105908`). 시험은 경로를 환경 변수로 넘겨 진행했다.

UI 글꼴(2026-11-01). 게임 폰트를 빌드 때 TTF로 바꾼다(`work/tools/hnf2ttf.py`, 결과는 `build/ui/ChronosGame.ttf`, 원본 파생물이라 저장소 제외). 본체는 `ft/kor9x14`, `ft/eng5x14`이고 `kor11x16`, `eng7x10`은 외곽선 마스크다. 한글은 8×4×4 조합형으로 표는 `hancode`, `type844`(초성 44, 중성 40, 종성 22바이트), 코드는 `haninfo`다. 한글 데이터는 머리글 9바이트 뒤이고 한 줄은 [오른쪽, 왼쪽] 순서다(처음에 8바이트 [왼쪽, 오른쪽]으로 잘못 읽어 `ㅔ`, `ㅐ` 오른쪽 기둥이 1줄 위로 밀렸고 사용자가 발견했다). `ㅐ`, `ㅔ`를 포함한 글자들이 게임 프레임에서 픽셀 일치한다. 폭은 오른쪽 끝 + 2, 공백 4로, 그 문장의 글자 위치와 일치한다. 1 em = 11픽셀이라 11dp가 게임 글자와 1:1이다.

네트워크 모드 오프라인화(2026-11-01). 내장 서버로 옮겼다. 분석과 정한 값은 `work/net-offline.md`.

## 주의

- 원본 게임의 저작권은 EA에 있다. 개인 플레이 범위로 두고 원본과 빌드 묶음을 공개하지 않는다.
- WIE는 MIT 라이선스다(저작권 고지 유지). 저장소 `AGENTS.md`는 파생 제품의 README와 화면에 출처 표기를 요구한다. 공유하지 않는 개인 빌드라도 크레딧 한 줄은 넣어 두면 된다.
- WIE 로컬 빌드에는 Sentry DSN이 들어가지 않는다(`option_env!("SENTRY_DSN")`, 빌드 시 미설정). `npm` 웹 빌드는 아직 확인하지 않았다.
- 세이브와 데이터는 `~/Library/Application Support/net.dlunch.wie/PD007589/`에 쌓인다.

짐가방 36칸과 허리주머니 99개(2026-11-01). `native/restored/bag.c`. 짐가방은 연결 리스트라 상한 `0x13ad90`, 그리기 `0x13aad8`(6×3 창을 커서 따라 스크롤, 스크롤바, 개수 표시), 저장 `0x13aa04`/`0x13aa74`(9000바이트, 실패하면 18칸 시절 5400바이트로 다시 읽음)만 옮겼다. 커서 이동 `0x13abc0`은 원래 아이템 수 기준이라 그대로다. `0x13aeb8`은 필터 목록이 4페이지를 넘으면 멈추도록 고쳤다. 허리주머니 슬롯당 수량은 `0x13b52c`의 10을 99로 바꿨다. 수량은 부호 있는 1바이트이고 스택 전체 버리기가 99를 빼므로 99가 상한이다. `work/saves/battle`에 임시 코드로 아이템을 채워 36칸 초과 거부, 스크롤, 99개 이동, 저장 뒤 재시작, 5400바이트 파일 변환을 확인했다. 창고와 상점 화면, 제련 등 필터 목록, 전투 중 사용은 실행해 보지 않았다.

상태창 위치(2026-11-01). `native/restored/hud.c`가 `0x141d00`을 감싸 개발자모드 `상태창`이 상단(기본)일 때 상태창을 y=0에, 미니맵을 y=50에 그린다. 하단은 원본을 그대로 부른다. `0x178a50`의 격자 지도는 y를 화면 높이로 직접 계산해서 그 호출 동안만 높이 값을 바꿔 넘긴다. 설정 버튼은 `ui.cpp`가 상태창 높이만큼 내린다. ITEM/MAP 표시와 획득 알림은 하단에 남겼다. 상단일 때 문양(`0xaf4` 그림 5번, 26×34, 아래가 잘린 그림)은 `0x1087e4`로 세로로 뒤집는다. 이 그림에 바 틀의 왼쪽 끝이 들어 있어 바와 Exp 줄도 세로 대칭으로 배치했다. HP가 위인 순서는 유지하고, 위 바가 원본 아래 바의 모양을 쓴다. 바의 틀, 끝 그림, 채움(`0x144284`)도 세로로 뒤집어 사선이 좌상에서 우하로 간다.

대사 진행 UI(2026-11-02). 대사 중 OK 버튼을 숨기고 화면 아래 55%(`#tap`, `code=-5`)를 누르면 넘어가게 했다. `AUTO`와 `LOG`는 `restored/dialog.c`다. `0x11bde0`(글 번호, 칸, 내레이션)을 감싸 기록을 모으고, `0x119e30`(스크립트 끝) 뒤 첫 대사에서 `+0x699`가 꺼져 있으면 기록을 비운다. 프롤로그의 맵 이동에는 기록이 이어지고 필드 혼잣말에서는 새로 시작하는 것을 확인했다. 자동 진행은 칸의 `+0x374 >= +0x370`(쪽 글 다 나옴)일 때 900ms + 바이트당 35ms(최대 5초)를 기다려 OK를 보낸다. 글의 색 표시(`&|${}opqrst`)는 다음 표시까지 이어지므로 줄 머리에 다시 붙인다. 시험: 480폭 터치 입력으로 새 게임 프롤로그. NPC 메뉴 대화와 선택지가 낀 스크립트, 키보드 Tab/L, 실기기는 미확인.

플레이리스트(2026-11-02). `native/restored/music.c`. `0x174188`(배경음 불러오기, 번호 0~21)과 `0x17d3ec`(배경음 재생)를 감싸 실제 재생한 곡만 저장 폴더 `PLAYLIST`(22바이트)에 남긴다. 효과음은 `0x17d2c0`이 따로 틀어 섞이지 않는다. 재생은 `audio.c`의 `audio_solo_*`로 게임 경로와 분리했다. 켜져 있는 동안 게임의 배경음 요청은 버리고 효과음만 받으며, 곡을 바꿀 때 CC120까지 보내 잔향을 끊는다. 닫을 때 환경설정이 쓰는 `0x17d49c(1, 1)`로 타이틀 음악을 다시 튼다. 배경음 설정이 0이면 틀지 않는다. 곡 이름은 데이터에 없다. `MAP/SC/%03d`의 오프셋 6 바이트가 맵의 곡 번호이지만 지역명과 잇는 자료는 찾지 못해 번호로 표기했다. 시험(임시 로그): 배경음 0에서 빈 목록 `0/22`, `work/saves/worldmap` 복사본으로 게임 진입 때 bgm013 해금과 재시작 뒤 유지, bgm019(32.9초)를 끝까지 재생해 다음 해금 곡 bgm000으로 넘어감과 커서 따라감, 정지 뒤 peak 0.000, 임시 코드로 효과음을 재생 중에 두 번 넣어 곡 위치가 끊기지 않고 게임의 재요청 bgm000이 무시됨, 닫은 뒤 bgm000이 처음부터 재생, 배경음 0일 때 닫으면 무음, 폭 240/480/640 표시, `--touch` 패드의 OK, 방향, 메뉴 버튼 동작. 귀로 듣는 확인, 실기기 터치, Windows와 Android 빌드는 하지 않았다.
